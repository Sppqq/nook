# Моды: как Nook расширяет сам себя

Мод — файл `~/nook/mods/<имя>.py` с функцией `setup(m)`. Подключается **на лету**, без перезапуска бота.
Ядро (`bot.py`) для новых возможностей не трогай: почти всё делается модом.

Полная шпаргалка API с рабочими примерами — `mods/_example.py` (прочитай перед первым модом).

## Порядок

1. Имя: латиница в нижнем регистре, цифры, `_` (`weather`, `daily_digest`). Файлы с `_` в начале не грузятся.
2. Напиши `mods/<имя>.py`: docstring (первая строка — название для хозяина) + `def setup(m): ...`.
3. `mods check <имя>` — загрузит вхолостую и покажет, что мод добавляет. Ошибка → исправь.
4. `mods reload` — бот перечитает моды и ответит, что загрузилось. Ошибка загрузки → исправь, повтори.
5. Хозяину коротко: что добавил и где искать (кнопка в меню или в «Ещё → Моды»).

## API (обработчики могут быть async или обычными функциями)

> Хозяин НЕ любит /команды: в Telegram-меню они не показываются. Делай кнопки (`button`, where=menu|mods) и `on_text`; команды — только как запасной вход.


| что | как |
|---|---|
| команда `/x` | `@m.command("x", "описание")` → `fn(ctx)`, `ctx.args` — текст после команды; вернуть строку = ответить |
| команда → задача агенту | `m.prompt_command("x", "описание", "текст задачи {args}")` |
| кнопка | `@m.button("Текст", icon="refresh", where="menu"\|"mods")` → `fn(ctx)`; `where="menu"` — в главное меню (не захламляй, только частое) |
| кнопка → задача агенту | `m.prompt_button("Текст", "задача", icon=..., where=...)` |
| свои кнопки в сообщениях | `m.btn("Текст", "ключ", "арг")` + `@m.callback("ключ")` → `ctx.arg`; callback_data ≤ 64 байт |
| фоновая задача | `@m.every(секунды)` → `fn()` (первый запуск через N секунд) |
| при загрузке | `@m.on_start` |
| перехват текста хозяина | `@m.on_text(r"regex")` → вернуть строку/True = обработано, None = дальше агенту |
| ответить | `await ctx.reply(text, [[m.btn(...), ...], ...])`, `await ctx.edit(...)` (заменить сообщение с кнопкой), `await ctx.toast("…")` |
| написать хозяину из фона | `await m.send(text, buttons, silent=True)` |
| отдать задачу агенту | `await m.agent("промпт")`; фоном, без прогресса (хозяину — только если есть что сказать): `await m.agent("…", background=True)` |
| быстрая модель | `text = await m.llm("промпт", system=None)` — Mercury 3, без инструментов, ~1 с, не тратит лимит Codex |
| shell | `code, out = await m.sh("cmd", timeout=60)` |
| хранилище | `m.state` (dict) + `m.save()` → `spool/mods/<имя>.state.json` |
| лог | `m.log.info(...)` → logs бота |

Иконки `icon=` — имена из `emoji.json` (home, status, check, clean, refresh, shield, node, bell, cal, spark, disk, ram, …).
Текст — markdown как в обычных ответах (`**жирный**`, `` `код` ``).

## Правила

- Ошибка в моде не роняет бота: хозяину придёт «Мод X упал» с кнопкой «Почини» — она будит тебя с traceback.
- Фоновая задача, упавшая 5 раз подряд, останавливается.
- Не блокируй event loop: долгие вычисления/HTTP — `await m.sh(...)` или `await asyncio.to_thread(...)`.
- Секреты — из `os.environ` (бот грузит `secrets.env`), не хардкодь в мод.
- Команды не должны совпадать с ядром (`start, start2, menu, status, limits, jobs, new, stop, watch, login, mods`) и с другими модами.
- Выключить/включить: `mods disable <имя>` / `mods enable <имя>`; список: `mods list`.
- Удалить мод — только с согласия хозяина (или если это твой черновик).

## Если всё-таки нужно править ядро (`bot.py`)

Только то, что модом не сделать (новый тип хука в mods.py, исправление бага ядра):
1. Бэкап: `cp bot.py bot.py.bak-YYYYMMDD-<что>`.
2. Правка, затем `python3 -m py_compile bot.py`.
3. `mods restart` — ядро перезапустится **после** того, как ты закончишь текущую задачу (твой ответ дойдёт).
   Перед рестартом бот сам проверит, что `bot.py` импортируется; если нет — не перезапустится и пришлёт ошибку.
   Последняя проработавшая минуту версия — `spool/mods/bot.py.good`.
4. Запиши в journal.md, что поменял в ядре.
