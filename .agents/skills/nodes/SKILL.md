# Ноды

Хозяин добавляет ноды в меню бота (Ноды → Добавить): бот один раз заходит по паролю, ставит **твой** ключ
(`~/nook/keys/id_ed25519`) и забывает пароль. Пароля у тебя нет и не будет — только ключ.

- `nodes` — список: имя (для команд), **название от хозяина** («Германия VPN»), адрес, ОС, root.
  Данные: `~/nook/nodes.json`, SSH-конфиг: `~/nook/ssh_config`.
- `nodes ИМЯ|НАЗВАНИЕ 'команда'` — выполнить на ноде; `nodes ИМЯ|НАЗВАНИЕ` — проверить связь.
  Хозяин говорит о нодах их названиями («почисти германию») — `nodes` понимает название и его часть.
  В ответах хозяину называй ноду её названием.
- Файлы: `scp -F ~/nook/ssh_config file ИМЯ:/path`, `rsync -az -e "ssh -F ~/nook/ssh_config" src ИМЯ:/dst`.
- Что за машина и что на ней — в `memory/notes.md`, раздел «Ноды». Узнал новое — допиши туда.

## Правила

- Те же правила, что и для этого сервера (AGENTS.md): не уничтожай данные без спроса, бэкап конфига перед правкой,
  проверяй результат, пиши в journal.md (с именем ноды).
- Если логин не root: `sudo -n` там может не быть — тогда скажи хозяину, что нужно.
  `rootdo` работает только на ЭТОМ сервере, не на нодах.
- Не трогай SSH-настройки ноды (sshd_config, authorized_keys, файрвол) без явного «да» — можно потерять доступ.
- Автонадзор следит и за нодами: не отвечает по SSH, процессор/память/диск ≥90% — тогда будит тебя со снимком
  процессов в момент пика. Некритичное чини сам (как здесь), потом коротко напиши хозяину.
- Нода не отвечает: сначала отсюда `nodes ИМЯ`, `ping -c3 адрес`, `nc -zv адрес порт` — сеть это, ssh или сервер лёг.
  Без доступа починить нельзя — скажи хозяину, что видишь (панель хостера, перезагрузка).
